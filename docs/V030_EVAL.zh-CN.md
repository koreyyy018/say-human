# v0.3.0 第二轮使用模拟与 GitHub 发布审查

时间：2026-10-19。评测者：项目实现助手；这是**开发自测与审查**，不是独立专家测评。无可用的 Cursor/Codex/Claude Code CLI，因此没有真实模型会话、真实加载监控、API 调用或用户盲测。

## 测试分层（不能混为一个成功率）

**A. 第 1 轮：v0.2.0 安装/路由基线。** 测试 15 行业 × 8 任务模板 = 120 个具有行业上下文的模拟请求，在 Cursor/Codex/Claude 三平台各检查一次，共 360 个静态契约记录。旧版 Cursor 虽有规则但 `alwaysApply: true`，Codex 缺少 `.agents/skills/`，Claude 不能在只复制 SKILL.md 后读取原仓库引用。该基线按照“必须同时满足自包含、可发现、按需路由”的**全部条件**计分 0/360；这不是说旧版 360 次实际使用全部失败，而是说明三个平台都至少缺少一项打包契约。

**B. 第 2 轮：v0.3.0 发现/触发模拟。** 15 行业 × 12 任务模板 = 180 条请求 × 3 平台 = **540 项静态检查**，结果 **540/540 满足本项目定义的契约**。模拟程序用独立关键词代理路由函数替代真实 Agent 的技能选择：它能发现非沟通编程任务应被排除，但**不能证明 GPT、Claude 或 Cursor 实际会这样做**。案例、路由判断和逐条结果保存在 `evals/v030_round2_retest.json`。

**C. 第 2 轮：离线 CLI 90 条真实执行回放。** 15 行业 × 三模式 Explain/Decode/Encode × 2 种语气 neutral/playful = **90 项 CLI parser/handler 调用**，结果 **90/90 满足自动契约**。实际输出和事实边界保存在 `evals/v030_offline_replay.json`。量化边界检查确认无新增数值，并在测试记录中保留“尚未上线”“仍需压测”“回归测试仍在进行”等未完成状态。它没有证明每条写作风格都优美。

**D. 仓库自动测试与安装实测。** 单元测试覆盖安装器干净安装、全量安装、dry-run、既有文件冲突原子性、`--force` 仅替换管理文件、符号链接拒绝、规则选择性、情绪不污染正文、打包内容同步。除此之外运行原有的离线资产及旧版回归测试。

## 实际发现与修正

1. v0.2 Cursor `alwaysApply` 侵入正常编程 → 新版仅在有描述匹配时触发，并增加可明确调用的 Cursor `/say-human` 命令。
2. Codex 没有标准 Skill 目录 → 新版提供 `.agents/skills/say-human/SKILL.md` 和参考文件。
3. Claude 单独复制时引用路径失效 → 新版将模式指南、准确性规范和 9 条原始比喻放进 Skill 自身的 `references/`。
4. 没有给外部项目的安全安装方式 → 新增只拷贝托管文件的安装器，避免修改用户项目的通用 Agent 规则。
5. 职场输出缺少情绪温度 → 新增“遇到真实困惑才承接一次”的规范，独立于 copy-ready 成品；CLI 提供 opt-in 语气。
6. 检测器误判“仍需压测／回归进行”→ 放宽检查器对合法进度描述的识别，而不是强行改坏原输出。

## 可复制的使用例子（人工审核说明）

| 真实感输入 | 期望 | 观察与评价 |
|---|---|---|
| “我搞不懂 RAG，能解释吗？” | 接住困惑，先解释检索再生成，承认可能检索到错误内容 | Skill 指令和 few-shot 包含正确说明；真实模型输出待验证 |
| “领导说‘闭环’，我很烦。” | 不推断人品，给责任人/截止时间追问句 | CLI 离线 Decode 能输出匹配与追问；语气包支持一句具体理解 |
| “修复扫码闪退，测试环境通过，还没上线。” | 不写成线上收益 | 离线 Encode 保留试验/上线阶段限制 |
| “用户请求修复函数编译错误。” | 不插比喻、不改变编码任务 | 新规则排除；目前只有静态代理触发验证，无实际 IDE 记录 |
| “把产品说法‘越快越好’变验收标准。” | 输出基线与可量化维度，不擅定数值 | Agent Skill 的 Align 已定义；离线 CLI 没有 Align 子命令 |

## GitHub 开发者视角：发布建议

**可以作为 public beta 公开仓库；尚不应宣称 production-proven Agent Skill。**

| 维度 | 评审 | 下一步 |
|---|---|---|
| 可发现/可安装 | **较好**：符合官方目录习惯，有安装器与检查 | 需要有真实 Cursor/Codex/Claude 环境的贡献者做截图/日志验收 |
| 提示词差异化 | **中等偏上**：基于真实场景比喻，讲 ROI 边界 | 与不使用 Skill 的模型做独立盲测，证明相对收益 |
| 真正内容质量 | **未充分验证**：离线主要是规则模板 | 随机抽样人工评分自然性、行业相关性与事实准确性 |
| 安全可信度 | **基础较好**：拒绝无授权命令/虚构收益，安装器不写通用规则 | Prompt injection 防护不能代替权限隔离、工具沙箱 |
| 开源可信度 | **中等**：MIT、CI、贡献指南、双语 README | 增加真实短视频/GIF 演示、CHANGELOG 发行标签、用户成功案例 |
| GitHub 星标潜力 | **不可推断**：没有真实受众转化/留存数据 | 发布后记录访问、安装成功、issue、7 日重复使用等 |

建议以一句清楚的价值承诺做首页：“A communication skill for coding agents: code correctly, explain clearly, report honestly.” 不要在 Star 或推文里声称 540 个“真实 Agent 使用成功”，更不要号称模型能力提升了多少百分比。

## 核心局限与风险

- 评测脚本自己定义了通过条件，不能代替独立测评。首轮 0 分来自严格全条件门槛，不是实际对话失败率。
- 所有行业情境为合成样本，不包含真实公司内部文件。
- 版本差异与用户本地已有 `AGENTS.md`、Cursor 自定义规则、Claude 权限设置都可能影响触发。
- `--force` 会替换同名受管文件；建议先提交 Git 方便回滚。
- 跨语言自然度仍需母语评审，尤其中文职场汇报目前多数仍属可编辑初稿。
