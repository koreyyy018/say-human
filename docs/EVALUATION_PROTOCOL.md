# Independent A/B skill evaluation (protocol, not a claim of improved performance)

**Hypothesis:** The Say-Human system instructions improve stakeholder communication relative to a neutral generic assistant prompt. This hypothesis has NOT been tested with live models by repository maintainers.

## 1. Review the cases

`evals/ab_cases.jsonl` includes 12 prewritten bilingual, cross-industry tasks. Extend this set with **consented, anonymized** real scenarios if possible. Avoid private company, customer or patient records unless separately authorized for your chosen LLM provider.

## 2. Choose a model and budget

Run a dry plan first:

```bash
python evals/ab_compare.py --max-cases 12
```

Execution requires explicit `--execute` and 2 model requests per case. Set `SAYHUMAN_API_KEY`, `SAYHUMAN_MODEL`, and optionally `SAYHUMAN_BASE_URL`. **No API key is bundled and no calls happen by default.** Inspect expected token costs with your provider *before* running. Results may contain sensitive content: store with appropriate controls. Stop if the provider fails; don't manufacture responses.

```bash
python evals/ab_compare.py --max-cases 12 --seed 47 --execute --out-dir evals/ab_runs/pilot
```

The output directory contains `blind_pairs.jsonl` for reviewers and **`private_answer_key.jsonl`** for the organizer. Keep the key hidden until scores are locked. Do not claim perfect blindness: style differences may reveal prompt conditions.

## 3. Independent human judging

Each reviewer scores both A and B on integer 1–5 for `factual_fidelity`, `clarity`, `usefulness`, `tone`. Enter into each pair's `scores.A` / `scores.B`. Recruit at least 2 reviewers, resolve disagreements and report inter-rater agreement. If multiple people score, keep separate reviewed files and disclose aggregation rules.

Scores are human judgements, not automatically generated by this tool. To summarize one reviewed file:

```bash
python evals/score_blind.py --pairs path/to/manually_scored_pairs.jsonl --key evals/ab_runs/pilot/private_answer_key.jsonl
```

Random order does not control for all order or judge bias; include more unseen examples and models before broad claims. Report cost/latency alongside quality, clearly distinguish **raw measurements** from predictions, and do not present descriptive sample differences as statistically significant.

## 4. Other controls

Use matched model/temperature/configuration for both conditions; randomize A/B display with fixed seed; avoid judging solely by length or tone; include failure examples and missed harmful claims; check both native and non-native English speakers for localization quality. Separate high-stakes legal/clinical validation from general communication usefulness.

`evals/run_v020.py` verifies offline rules only, not these independent quality dimensions.
