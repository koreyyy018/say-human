# Say-Human v0.5.0 跨行业 Decode A/B 验收（发布候选）

> 本报告由本地代码和规则回放得到，**不是 GPT / Claude / Cursor / Codex 的真实回答对照**。不将规则覆盖率当作用户满意度；本次重点解决 Decode 冗余免责声明、词库覆盖和中文未命中退化。

## 1. 测试设计

- **历史原样复跑**：沿用 v0.4.0 的 10 轮 × 每轮 20 条（共 200 条，Explain/Decode/Encode/Align 各 50）；把历史原版回答和新版同一输入放在 CSV 中，通用模板组也保留。
- **Decode 专项新增**：另外 10 个行业 × 20 条（共 200），包含 80 条新增行业词、50 条旧词、40 条转述目标、20 条本来就直接的普通表达和 10 条术语提及/字面意义反例。
- 旧版运行原始 v0.4.0 CLI，新版运行 v0.5.0 CLI。所有输出都保留；没有使用付费模型。测试由开发者自行设计，不能用作独立行业水平评分。

## 2. 最关键结果

| 维度 | v0.4.0 | v0.5.0 | 解读 |
|---|---:|---:|---|
| 历史 50 个 Decode 输入出现固定免责声明/无命中提示 | 50 | 0 | **表达缺陷已在测试集上修复** |
| 历史 50 个 Decode 的可识别黑话 | 45 | 45 | 旧能力未退化，另外 5 条是普通语句 |
| 新 200 个 Decode 中含精确目标词条匹配 | 0 | 130 | 词库扩充带来的**已知词覆盖提升**；不能外推任意句子 |
| 新 200 个 Decode 中任意词库命中 | 11 | 130 | 旧版有 11 条别名/子串碰巧命中 |
| 新 200 个 Decode 中输出固定免责声明/无命中提示 | 200 | 0 | 规则检查通过 |
| 新 200 个 Decode 中建议切换 --llm 的无命中提示 | 189 | 0 | 中文兜底替代英文式失败提示 |
| 新 200 个 Decode 中运行错误 | 0 | 0 | CLI 路径都可执行 |
| 20 条清晰表达被迫追问 | 未做语义评分 | 0 | 避免没必要的“谁负责何时完成” |
| 10 条标题/课堂/字面语境误识别为项目黑话 | 未做语义评分 | 0 | 防止高覆盖导致乱解码 |

新版 200 条的处理路径：**130 条词库命中、39 条语义目标兜底、31 条识别为普通表述**。只有前 130 条可算“词库命中”；另外 70 条是有条件的解释策略，**不算术语识别准确率**。

## 3. 代表性前后对照

### 例 A：老板说“赋能”

**原始请求：** AI/SaaS 负责人说“要赋能一线团队”，但没说明负责人和时间。

- v0.4.0：先发“以下只是可能的解读，不能仅凭黑话推断发言者的真实意图”，然后才给出定义与追问。
- v0.5.0：**一句人话：** 提供工具、培训或资源，让一线团队真正能做成事。**可以回：** “我们先把负责人和截止时间定下来，我再按这个安排推进，可以吗？”

### 例 B：专业词“危急值闭环”（医疗）

- 过去：未识别词库，建议加 `--llm`。
- 现在：**一句人话：** 重要的检查异常要及时通知负责医生，并确认得到处理。**建议追问：** “从发现到医生接收需要多久，记录由谁负责？”

### 例 C：未知词的自然语言改写

“厂长说新品试做完之后还要经得起大批量生产。”

- 过去：没有对应词条时给出固定的“未命中”提示。
- 现在：可提炼为**满足量产验收条件之后再切换阶段**，并询问具体质量、产能和交付标准。不是假装识别了某个行业缩写。

### 例 D：本来就明确的安排

“请把会议室钥匙还给前台。”

- 新版：**要求很明确：请把会议室钥匙还给前台。** 不额外追问负责人、KPI、验收流程。

## 4. 局限与剩余质量风险

1. **130/130 是被选入新词库的已知词测试**，不是对未来任意黑话 100% 的识别率；新词扩充本身就直接提高命中。
2. 语义兜底是基于语言线索的启发式规则，遇到绕口句、多层责任关系、隐喻或高风险组织决定，仍可能误判。尤其不要猜“人员优化一定是裁员”等动机。
3. 当前新版在 Explain 模式仍有 5 条“双概念比较”旧缺陷；Encode 模式原有的部分中文病句也未在此次 Decode 专项中全面修复。**本轮版本不声称解决这两个问题。**
4. 词库解释是原创编辑和合成整理，**不是官方行业法规解释或逐条专家审核**。在医学、金融、安全与 HR 高风险场景中，应核对实际组织流程。
5. 只验证实际运行的离线 Python 程序、文件一致性和安装结构；没有真实 AI Agent 客户端或跨模型盲评，不应在 GitHub 宣称大模型质量提升百分比。

## 5. 下一阶段开发建议（产品经理优先级）

- **P0**：给英文行业术语与冷门缩写补充准确双语释义，并增加人工专家复核样本；部分新词条当前英文释义仍是占位式通用描述。
- **P1**：修复 Explain 多概念比较输入；改进 Encode 中文病句，以降低首次体验损耗。
- **P1**：把跨行业聊天资料中的实体、交付结果、时间和指代提取成结构化中间层，替代越来越多的正则规则；真实模型环境下应做带来源核对的质量测试。
- **P2**：先做 30–50 个真实用户双盲 A/B，在相同底座模型下对比是否加载 Skill，独立评估准确性、理解成本、情绪自然度、任务完成度。
