# v0.4.0 发布候选版：测试说明与开源维护者评估

## 范围

本轮基于 v0.3.1 迭代：五种 Skill 工作模式（新增 Reply）、受众关系/渠道/目的/风险/情绪框架、15 行业示例、局部情绪回应、离线 Align，以及第三方模型调用时的用户上下文传递。

它并不自动让任意话题都变优秀：广泛适配的含义是**对沟通类任务进行适当翻译**，不是代替工程、合规、心理咨询或个人判断。

## 新发现的失败及修复

1. 中文数字与汉字相邻时，旧版审核模式可能不把 `效率提升40%` 算作新数字——已修复，现会报警。
2. 离线缺少可运行 Align 命令——现能基于目标给出指标名称、试验建议、缺失的阈值/审批决定，不编造 KPI。
3. 旧版文本中出现 `把客户登录的卡顿问题已修复` 等不自然措辞——新增常见中文短句规则，并保留“未上线/仍需压测”等限定条件。仍无法像 LLM 一样处理所有自然语言。
4. 情绪支持以前偏模板——现优先对输入具体障碍（技术词、黑话、上线不确定）作简短回应；正式交付文本始终独立。

## 本地测试方法与边界

- v0.3.1 的 127 项单元测试在基线全部通过；v0.4.0 新增 18 项回归测试，目前合计 145 项通过。
- 新建 `evals/v040_release_gate.py`：15 个行业×10 个场景 + 50 个对照/边界场景，执行 200 条离线 Python 函数调用，并把输入、输出、判定条件保存到 `evals/v040_release_results.json`。
- 场景模拟日常职场说法，**不是**真实公司数据或随机采样真实用户；部分场景仅改变业务名词，不能把 200 条解释为 200 种独立语言能力。
- 自动判定主要测试结构、缺失指标、上线状态、证据边界及情绪分离，不衡量类比创造力、共情满意度或企业业务效果。
- 三端目录可被安装器复制，不等于模型真实加载/触发/遵循 Skill 指令；没有运行真实 Cursor、Codex、Claude Code 会话。远程 Reply 路径通过模拟提供者测试，没有向商业模型发送请求。

## 开源开发者层面评估

| 维度 | 现状 | 风险 |
|---|---|---|
| 定位 | 面向沟通翻译的 5 模式 Skill，非普通万能提示词合集 | 对不需要沟通翻译的编码任务必须保持不触发 |
| 安装 | Cursor 项目规则+命令、Codex/Claude 自包含 SKILL、安装器 | 尚未用真实 Agent 版本逐一端到端确认 |
| 成果真实性 | 保守型 Encode/Report、启发式 Audit | 不能证明语义正确，也可能漏报伪造指标 |
| 语言自然性 | 增加情绪语境、对象/渠道策略与中文常见结构清理 | 离线 Encode 对复杂语言仍可能机械或错误 |
| 跨行业 | 15 行业假设用例与风险提醒 | 缺少真正从行业用户获取的反馈 |
| 维护工程 | MIT、贡献说明、CI、回归数据、明确版本 | GitHub Actions 尚未在用户自己的公开仓库验证 |

## 发布决策

**建议：公开仓库 Public Beta ✅；不可宣称生产级或真实三平台 Agent 性能已通过 ❌。**

发布首页的主张应是：**Code correctly. Explain clearly. Report honestly.** 不要承诺“万金油万能回答”；让用户知道它专为沟通翻译提供可复用流程和事实边界。真实价值验证在公开后，通过收集匿名真实使用样本 + 有无 Skill 的模型盲测完成。
